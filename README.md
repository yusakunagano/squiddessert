# squiddessert

## AI職業サポート

10 問または 20 問の質問に答えると、Google Gemini（`gemini-flash-lite-latest`）があなたの性格と向いている職業を診断します。
10 問答えたところで「ここで結果を見る」か「あと 10 問答えて詳しく診断する」かを選べます。10 問で見た結果からも、残りの 10 問に答えて診断し直せます。
診断には 30 秒〜1 分ほどかかり、待っている間はミニゲーム「コバエたたき」で遊べます。
結果には、あなたの性格、いちばん向いている職業（名刺風のカード）とその職業の年収の目安、日本で就いている人の数、業界の楽しいこと・大変なこと、これから訪れる変化、代表的な会社 20 社、役立つ資格（最大 10 件）、仕事タイプ、傾向（創造力・協調性・分析力・行動力）、ほかに向いている職業 2 つ、向いていないかもしれない職業 2 つ、一緒に働くと相性の良い職業の人・ぶつかりやすい職業の人（うまく付き合うコツ付き）、結婚するなら相性の良い職業の人、強み、生活する上で気を付けること（ひとつながりの文章）、最初の一歩のアドバイスが表示されます。
結果には、向いている職業の求人をリクナビNEXT（転職）・リクナビ（新卒）で探すリンク（Google のサイト内検索）も表示します。
結果の最後には、診断された職業について AI に質問できるチャットがあります（1 回の診断につき 3 回まで）。「結果をすべてコピー」で結果・回答・チャットをまとめてコピーでき、ChatGPT・Gemini・Claude などに貼り付けて相談を続けられます。

- `job/index.html` … 診断ページ（静的 HTML）
- `api/diagnose.js` … 診断を行うサーバーレス関数（Vercel 形式、Gemini API を使用）
- `api/chat.js` … 職業についてのチャットに答えるサーバーレス関数
- `api/_shared.js` … 上の 2 つで共通の処理（Gemini の設定、CORS、エラー処理）

### API キーの発行

1. [Google AI Studio](https://aistudio.google.com/apikey) に Google アカウントでログインし、API キーを作成
2. キーは GitHub に書き込まず、下の手順で Vercel の環境変数に設定

Gemini API には無料枠があります（回数の上限あり）。無料枠では送信内容が Google のサービス改善に使われる場合があるため、公開前に最新の料金と利用規約を確認してください。

### デプロイ（Vercel）

1. このリポジトリを Vercel にインポート
2. 環境変数 `GEMINI_API_KEY` を設定
3. デプロイ後 `https://<your-app>.vercel.app/job/` を開く

API キーはサーバー側だけで使われ、ブラウザには公開されません。利用者が API キーを入力する必要はありません。

GitHub Pages の `job/` ページから使う場合は、`job/index.html` の `API_ORIGIN` に Vercel の URL（`https://squiddessert.vercel.app`）を設定済みです。
API は `https://yusakunagano.github.io` からの呼び出しを許可しています（`api/_shared.js` の `ALLOWED_ORIGINS`）。

### ローカルで動かす

```bash
npm install
GEMINI_API_KEY=... npx vercel dev
# → http://localhost:3000/job/
```

## Gemma 4 × Gemini Flash 比較

同じコンテキストと質問を Gemini Flash と Gemma 4 に投げ、答えと**返答速度**を並べて比べるページです。どちらが良い答えかをブラインド（どちらのモデルか伏せた状態。切り替え可）で選ぶと、勝ち数と平均の返答速度がブラウザに集計されます。

- `model-compare/index.html` … 比較ページ（静的 HTML）。コンテキスト欄（任意）と質問プロンプト欄があり、コンテキストはブラウザにだけ保存されます（リポジトリには置かない）。
- `api/model-compare.js` … 2 つのモデルを並列で呼び、答えと返答にかかった時間（ミリ秒）を返す関数。どちらにも同じ形式で、会話の最初の発言にコンテキストを付けて渡します。続けて質問すると、モデルごとに「自分の前の答え」を含めた履歴を渡して会話を続けます（最大 10 回。両方成功した回だけ会話と集計に加えます）。
- API キーは職業サポートと同じ `GEMINI_API_KEY`（Google AI Studio のキー）を使います。
- モデル名は環境変数 `FLASH_MODEL`（既定 `gemini-flash-latest`）と `GEMMA_MODEL`（既定 `gemma-4-31b-it`）で変えられます。どちらかが失敗したときは、ページに使えるモデル名の一覧が出ます。
- Google 側が 5xx を返したときは最大 2 回やり直します（503 は 2 秒待って、500 は生成設定を外して）。返答速度にはこのやり直しの時間も含まれます。

## AIサポート（決済アプリのプロトタイプ）

`pay-ai-support/` のホームのAIアシスタントで「お得な情報を知りたい」を押したときだけ、`api/pay-assistant.js` 経由で Gemini に問い合わせます（それ以外の質問はページ内のルールで回答）。
APIキーは職業サポートと同じ `GEMINI_API_KEY`（Vercel の環境変数）を使います。

- AI に渡すのは、ページに表示している公開情報と、利用者が許可した項目（残高・ポイント／利用明細／カード請求）だけです。
- AI は答えるほか、送金・利用履歴・口座登録・利用サービスの画面を開くこと、情報提供の許可を求めることができます（送金そのものは行いません）。
- API に接続できないときは、ページ内の簡易ルールで答えます。

### お得な情報：キャンペーンの事前読み取り

ホームのAIで「お得な情報を知りたい」を押したときは、キャンペーンページを**事前に読んで保存したデータ**で案内します（チャットのときはページを読みに行きません）。

- `scripts/crawl-campaigns.mjs` … キャンペーンページの特集一覧（タイトル・種別・エントリー要否・期間・リンク先）と、各リンク先の詳細（還元・上限・対象・エントリー方法・注意）を Gemini で読み、`pay-ai-support/data/campaigns.json` に保存します。
- `.github/workflows/crawl-campaigns.yml` … 上のスクリプトを毎日 1 回（日本時間 5:17）実行し、内容が変わったときだけ main にコミットします。手動で実行するときは GitHub の「Actions」→「キャンペーンの事前読み取り」→「Run workflow」。
- `api/_campaigns.js` … ページの読み取り（スクリプトと API で共通）。同じサイト内のリンクだけを読み、ページの取得に成功したと確認できたときだけ内容を採用します。
- 入力した質問・音声は、AI（`api/pay-assistant.js` 経由の Gemini）が答えます。質問候補のボタンは、ページ内のルールで即答します。「送金したい」「履歴を見たい」のように画面を開く依頼や、「お得」「キャンペーン」を含む質問は、AI を使わず直接動かします（お得な情報は専用の AI モード）。AI につながらないときはルールで答えます。短時間（5 分に 30 回）を超える質問は断ります。
- `api/pay-assistant.js` … チャットのたびに保存データを取り込み、**一覧（タイトルなど）は常に、詳細は利用者の話に合う上位 5 件だけ**を AI に渡します。保存データがないときは、その場でページを読み、それも読めなければ画面の固定の概要で答えます。
  特集を紹介するときは、AI が選んだ特集の id を、保存データにある本物の URL（同じサイト内のものだけ）に置き換えて、返事の下にリンクとして表示します（AI に URL は書かせません）。

セットアップ：GitHub のリポジトリの Settings → Secrets and variables → Actions に `GEMINI_API_KEY`（Vercel に設定しているものと同じキー）を登録します。

```bash
# 手元で試すとき
GEMINI_API_KEY=... node scripts/crawl-campaigns.mjs
```

### 銀行口座の登録（`pay-ai-support/register.html`、プロトタイプ）

実際のアプリに近い 16〜18 ステップ、5 つの段階（準備 → 口座 → 本人確認 → 認証 → 設定）の流れです。流れの本体は `register.js` です。

- **準備**：登録の流れと準備するもの／規約への同意／SMS による電話番号の確認
- **口座**：金融機関の検索（かな・カタカナ・種別）／登録方法の選択（金融機関のサイトで承認 or キャッシュカードの暗証番号。金融機関ごとに選べる方法が違う）／預金種別・支店・口座番号／口座名義と生年月日
- **本人確認**：書類の選択（マイナンバーカードは IC 読み取り or 撮影で分岐。書類ごとに撮影する面が違う）／顔の撮影／読み取り内容の確認／審査待ち
- **認証**：金融機関のサイトにログイン → ワンタイムパスワード → 提供情報の承認、または暗証番号の入力
- **設定**：チャージ上限・オートチャージ／登録内容の確認（各項目を修正できる）／完了
- つまずく場面：メンテナンス中の金融機関、当座預金、名義の不一致、18 歳未満、SMS コードの誤り、書類・顔の撮影失敗、IC 読み取り失敗、ログイン・暗証番号のロック、連携の拒否（登録方法の選択に戻る）
- 途中保存：「あとで続ける」で中断でき、同じタブなら「続きから再開」できる（暗証番号・パスワード・認証コードは保存しない）
- AIサポートは画面ごとに候補と答えが変わり、エラーが出ているときはその説明から始める

画面内の「デモ：」は動作確認用の値です（SMS コード `123456`、ネットバンキングのパスワード `bank1234`、ワンタイムパスワード `654321`、暗証番号 `1234`、アカウントの氏名「ヤマダ タロウ」）。

### デザインチェッカーの SEO・OGP・AIO チェック（`design-check/`）

「URLを入力」で URL を入れると、デザインのチェック（従来どおり）に**加えて**、結果の下に「SEO・SNS 共有（OGP）・AIO チェック」が追加で表示されます。URL の入力欄の下の「SEO・OGP・AIO だけチェックする」ボタンなら、Gemini の API キーなしで、このチェックだけを実行できます。

- **基本の SEO**：HTTPS・HTTP ステータス・転送・タイトルと説明文の長さ・h1 と見出しの階層・canonical・noindex・viewport・lang・画像の alt・リンク文言・robots.txt・sitemap.xml・応答と HTML の大きさ
- **SNS 共有（OGP）**：og:title・og:description・og:image（https か・実際に表示できるか）・og:url・og:type・twitter:card・og:site_name と、共有したときの見え方のプレビュー
- **AIO（AI 検索・生成 AI 向け）**：構造化データ（JSON-LD）・運営者とページの種類・FAQPage・AI クローラー（検索側／学習側に分けて robots.txt の許可を確認）・llms.txt（任意）・本文が JavaScript なしで HTML に含まれているか・冒頭で要点を述べているか・箇条書きと表・著者／日付／運営者情報（信頼性）・main/article・パンくず
- 項目ごとに「良好／要確認／要改善」と改善案を表示し、各グループを 100 点満点で採点して、「まず直したいところ」を最大 5 件まとめます。機械的に調べた簡易診断で、検索順位や AI での引用を保証するものではありません。
- `api/seo-check.js`（Vercel）が、URL のページ・robots.txt・sitemap.xml・llms.txt・og:image を取得して判定します（AI は使いません）。判定のルールは `api/_seo.js`、安全な取得は `api/_safefetch.js` です。
- **取得の安全対策**：http / https のポート 80・443 だけ／ID・パスワード入りは拒否／接続の直前に接続先 IP を確認し、非公開のアドレス（127.x・10.x・192.168.x・169.254.x・IPv6 の内部向けなど）は拒否（名前解決のすり替え対策）／転送は 1 回ずつ同じ検査をして最大 5 回／大きさと時間に上限／同じ接続元から 10 分に 20 回まで。
- テスト：`npm test`（判定のルール・取得の安全対策・API を、手元の簡易サーバーで確認します）

### AIエージェントを使う（プロファイリング、デモ）

ホームのAIアイコンを開くと、質問候補の先頭に「🧠 AIエージェントを使う」があります（「プロファイリングして」と入力しても始まります）。選ぶと、次の順に進みます。

1. 説明 → **アカウント情報の連携（連携する項目は 1 つ）**：「アカウント情報」の 1 項目を許可すると、利用明細・残高とポイント・カード請求を、まとめて連携します（ほかのAIの質問では、従来どおり項目ごとに選びます）
2. **プロファイリングの実行の確認**：使うデータ・わかること・推定しないこと（健康・信条・家族構成などのセンシティブな情報）・使い道（おすすめの提案だけ。広告や第三者提供には使わない）・保存（この画面を閉じるまで）を見せて、「プロファイリングを実行」か「やめる」を選ぶ
3. 実行：8 つのステップが進み（約 4〜5 秒）、詳しいプロファイルが表示される
4. 「おすすめを見る」「根拠を見る」「プロファイルを削除」「連携も解除する」

プロファイルの内容（9 項目。各項目はタップで開け閉めでき、グラフつき）：タイプ名とひとこと／ひとことで言うと（文章）／傾向のタグ／数字で見る利用（8 指標）／支払い方法と金額の大きさ／どこで使っているか（場所の種類）／いつ使っているか（曜日・時間帯）／月ごとの推移と来月の見通し／強みと気をつけたい点／特典の活用度（ランク特典の上限・提携銀行・支払い元）／優先度つきのおすすめ（最大 5 件）／このプロファイルについて（推定の確からしさ・使った情報）。

- デモなので AI は呼ばず、サンプルの利用履歴（直近約 6 週間・28 件。10 月・9 月の合計は今月・先月の利用額と一致）に、決まったルールを当てて作ります（`agent.js` の `buildProfile`）。実際のデータやサーバーには何も送りません。
- 許可していない項目の情報は使いません。結果には、支払いの方法・金額・日付・時刻・場所の種類から決めた傾向だけを載せ、根拠も確認できます。
- 実際のサービスにするときは、利用目的・保存期間・拒否の方法をプライバシーポリシーに明記し、同意を得る必要があります。

### 特集一覧と、AIから特集一覧へ飛ぶ（`pay-ai-support/campaigns.html`）

- **特集一覧のページ**：特集を並べて、種別（d払い／dポイント／その他）・エントリーが必要なものだけ・キーワードで絞り込めます。各特集に、種別・エントリーの有無・期間・「くわしい条件を見る」（還元・上限・対象・エントリー・注意）・公式ページへのリンクを表示します。
- **データ**：`pay-ai-support/data/campaigns.json`（毎日の事前読み取りで作られる）があればそれを表示します。なければ、公開情報をもとにしたサンプル 3 件を表示し、「サンプルの一覧です」と明記します。外部の文字はすべてエスケープして表示し、リンクは、キャンペーンの公式サイトの https のものだけを使います（それ以外は、公式のキャンペーンページに差し替え）。
- **AIから飛ぶ**：ホームのAIの「お得な情報」に、「他の特集を見る」を出します。押す、または「他の特集を見たい」「特集一覧を見せて」「ほかの特集は？」「すべての特集を教えて」と入力する（音声も同じ）と、AIを使わずに特集一覧へ移ります。AI が返した「他の特集」の質問候補は外し、こちらで 1 つだけ付けます。AI につながらないときも出ます。
- **AI の判断でも飛べます**：AI が、利用者がほかの特集をまとめて見たがっていると判断したときは、特集一覧を開く指示（`open_campaigns`）を返します（`api/pay-assistant.js`）。
- 「特集を教えて」のように、一覧ではなく特集の紹介を求める質問は、これまでどおり「お得な情報」のAIが答えます。

### 倍率アップAI：提携銀行の口座の有無 → 銀行口座の登録へ

利用サービス画面の「倍率を上げるには？」などで、「提携銀行の口座はお持ちですか？」（持っている／持っていない）をたずねたあと：

- **持っていない**：口座がないと +2% の特典は使えないことを伝え、その場で**銀行口座登録の画面**（`register.html`）へ移ります。
- **持っている**：これまでどおり、利用額をたずねて、増える見込みと手順を示します。最後の「手続きを始める」を押す（または「手続き」と入力する）と、銀行口座登録の画面へ移ります。
- AI（入力した質問）が、口座を持っていない・これから作る、と判断したときも、銀行口座登録の画面を開く指示（`open_register`）を返します。

## ニャーズ

猫のキャラクター「ニャーズ」と話せる、チャット形式のひらめきの相棒です（ファイル名・URL は `nuse` のままです）。今日の出来事・気分・キーワードなどの断片を話しかけると、Gemini が会話で、アイデアや問いかけを返します。トーン（やさしく／大胆に／遊び心）を選べます。

- `nuse/index.html` … チャットページ（静的 HTML）。Enter で送信、Shift+Enter で改行。1 つの会話で 10 回まで話せ、「最初から」でやり直せます。
- `api/nuse.js` … 会話の履歴を受け取って返事を返す関数。1 回の入力は 1000 文字まで、同じ接続元から 1 分あたり 15 回まで。入力は命令ではなく素材として扱うよう指示しています。
- `tests/nuse.test.mjs` … 自動テスト（`npm test`）

### Google カレンダー連携（開発中）

チャットの途中で「今日の一歩を予定に追加」を押すと、会話から予定の下書き（タイトル・長さ・メモ）を作り、確認・編集のうえで、利用者自身の Google カレンダーに追加します。

- 利用者ごとに Google ログインします（Google Identity Services）。予定を作る権限（`calendar.events`）だけを求め、トークンはブラウザの中だけで使い、サーバーへの送信も保存もしません。
- `api/nuse.js` は `action: "step"` で下書きを返すだけで、カレンダーには触れません。

**使えるようにする手順（1 回だけ）**
1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「Google Calendar API」を有効にする
2. 「OAuth 同意画面」を設定し、スコープに `.../auth/calendar.events` を追加。公開前は「テスト」状態で、テストユーザー（最大 100 人）に自分のメールを登録
3. 「認証情報」→ OAuth クライアント ID（種類：ウェブ アプリケーション）を作り、承認済みの JavaScript 生成元に `https://yusakunagano.github.io` を登録
4. 発行された**クライアント ID**（シークレットは不要）を `nuse/index.html` の `GOOGLE_CLIENT_ID` に入れる
5. 一般公開するには、Google の OAuth アプリの審査（確認）が必要になる場合があります。審査が済むまでは、テストユーザーだけが使えます
